# Именование полей context: как выбрать имя и не уронить документ

> Соглашение общее для двух библиотек: **LogSymfony** (`ContextEnricher::contextTypeCorrector()`)
> и **PHPErrorCatcher** (`PhpErrorCatcher::contextTypeCorrector()`). Обе пишут в один
> кластер OpenSearch, поэтому таблицы правил в них обязаны совпадать слово в слово.
> Уточняет §4.5 и §4.7 [LoggingRules.ru.md](LoggingRules.ru.md).

## 0. Зачем это существует

В индексах OpenSearch не выставлен `ignore_malformed`. Поле получает тип от первого
документа, в котором встретилось: пришёл `"order_count": 5` - поле стало `long`. Когда
следующий сервис пишет в то же поле `"order_count": "5"`, OpenSearch **молча отбрасывает
весь документ целиком**, а не одно поле - лог просто не появляется, без ошибки и без
следа. Поэтому имя поля в context - это объявление типа, а не украшение.

## 1. Правило целиком, одним абзацем

**По умолчанию любое поле - строка.** Ключ режется на сегменты по `_`; **последний
сегмент** решает тип (`retry_count` → int, `item_price` → float, `debug_flag` → bool);
если последний сегмент ничего не значит, смотрится **первый** - но только на булевы
префиксы (`is_active`, `has_access`). Совпадение всегда по **целому сегменту**, никогда
по подстроке: `report` не видит `port`, `datetime` не видит `time`, `account` не видит
`count`. Ничего не подошло - поле остаётся строкой (а массив/объект вообще не трогается).
Значение, которое нельзя привести без потерь (`retry_count = "много"`), тоже падает
обратно в строку; `null` всегда остаётся `null`.

Порядок разрешения, первое совпадение выигрывает:

1. **`suffix`** - escape hatch: последний сегмент `int` / `float` / `bool`. **Высший
   приоритет**, бьёт всё остальное, включая `reserved`.
2. `reserved` - служебные поля библиотеки.
3. `exact` - весь ключ целиком (уровень переопределения для проекта).
4. `word` - последний сегмент.
5. `prefix` - первый сегмент, только для ключей из 2+ сегментов.
6. ничего не совпало - строка по умолчанию.

## 2. Словарь канонических слов

### 2.1 Последний сегмент → **int**

| Слово      | Смысл                                  | Пример ключа       |
|------------|----------------------------------------|--------------------|
| `int`      | escape hatch, высший приоритет (§2.5)  | `external_int`     |
| `id`       | идентификатор (см. §2.6)               | `user_id`, `id`    |
| `count`    | счётчик чего-либо                      | `retry_count`      |
| `cnt`      | то же, короткая форма                  | `row_cnt`          |
| `num`      | номер / количество                     | `page_num`         |
| `qty`      | количество товара                      | `item_qty`         |
| `total`    | итоговое **количество** (не деньги)    | `order_total`      |
| `sum`      | сумма **счётчиков** (не деньги)        | `attempt_sum`      |
| `size`     | размер (элементов или байт)            | `queue_size`       |
| `bytes`    | размер в байтах                        | `payload_bytes`    |
| `len`      | длина                                  | `message_len`      |
| `length`   | длина, полная форма                    | `body_length`      |
| `limit`    | лимит выборки                          | `page_limit`       |
| `offset`   | смещение выборки                       | `page_offset`      |
| `page`     | номер страницы                         | `page`             |
| `depth`    | глубина (рекурсии, дерева)             | `trace_depth`      |
| `attempt`  | номер попытки                          | `retry_attempt`    |
| `retries`  | сколько раз повторили                  | `job_retries`      |
| `level`    | числовой уровень                       | `nesting_level`    |
| `port`     | сетевой порт                           | `db_port`          |
| `status`   | **числовой** код состояния             | `http_status`      |
| `time`     | unix-время в **целых** секундах        | `start_time`       |
| `seconds`  | длительность в целых секундах          | `wait_seconds`     |
| `ttl`      | время жизни, секунды                   | `cache_ttl`        |

### 2.2 Последний сегмент → **float**

| Слово      | Смысл                                  | Пример ключа       |
|------------|----------------------------------------|--------------------|
| `float`    | escape hatch, высший приоритет (§2.5)  | `external_float`   |
| `money`    | деньги                                 | `order_money`      |
| `amount`   | деньги (сумма к оплате)                | `pay_amount`       |
| `price`    | цена за единицу                        | `item_price`       |
| `duration` | длительность с долями секунды          | `job_duration`     |
| `rate`     | частота / доля                         | `hit_rate`         |
| `ratio`    | отношение                              | `fill_ratio`       |
| `percent`  | проценты                               | `cpu_percent`      |
| `avg`      | среднее                                | `load_avg`         |
| `score`    | балл / оценка                          | `bot_score`        |

### 2.3 Последний сегмент → **bool**

| Слово      | Смысл                        | Пример ключа     |
|------------|------------------------------|------------------|
| `bool`     | escape hatch, высший приоритет (§2.5) | `external_bool`  |
| `flag`     | признак                      | `debug_flag`     |
| `enabled`  | включено ли                  | `cache_enabled`  |
| `success`  | успешно ли завершилось       | `success`        |

### 2.4 Первый сегмент → **bool**

Работает только у ключей из двух и более сегментов (одинокое `is` - это слово, не префикс)
и только если последний сегмент ничего не решил.

| Префикс   | Пример ключа     |
|-----------|------------------|
| `is`      | `is_admin`       |
| `has`     | `has_access`     |
| `can`     | `can_edit`       |
| `should`  | `should_retry`   |
| `allow`   | `allow_list`     |
| `enable`  | `enable_cache`   |
| `use`     | `use_cache`      |

Строки `''`, `'0'`, `'f'`, `'false'`, `'n'`, `'no'`, `'off'` (в любом регистре) - это `false`.
Легаси-значение `'F'` из БД именно поэтому не превращается в `true`.

### 2.5 Escape hatch `_int` / `_float` / `_bool`

Ключ, у которого **последний сегмент** - `int`, `float` или `bool`, получает этот тип
**всегда**: это отдельное ведро `suffix` на самом верху цепочки (§1), оно бьёт `reserved`,
`exact`, `word` и `prefix`. Поэтому `price_int` - **int** (а не float по слову `price`),
`count_bool` - **bool**, `seconds_float` - **float**.

Это единственный способ продавить тип, который ничем не переопределить сверху. Используй,
когда поле приходит из чужой системы, или когда обычное имя даёт не тот тип и переименовать
поле по-другому нельзя.

Escape hatch `_string` **не существует.** Ключ, который обязан остаться строкой, пиннится
только через конфиг (`exact` / `reserved`) - см. §5.

### 2.6 `id` - это **int**

В этих проектах идентификатор - auto-increment integer из MariaDB, и владелец хочет по нему
range-запросы (`order_id > 5000`) и агрегации, поэтому `id` - int-слово. Как **последний
сегмент** оно покрывает и голый ключ `id`, и любой `*_id`: `user_id`, `order_id`, `smq_id`.

Совпадение только по целому сегменту, поэтому `uuid`, `android`, `valid` и camelCase
`orderId` (в нижнем регистре - один сегмент `orderid`) идентификаторами **не** считаются и
остаются строками.

**Не-числовой id надо явно пиннить строкой** - и никогда не полагаться на «нескастуемое
падает в строку»: этот фолбэк держится ровно до того дня, когда кто-то передаст значение из
одних цифр. Библиотека сама пиннит `request_id` (UUID из `RequestId::get()` либо
входящий `X-Request-ID`): `reserved` в LogSymfony, `exact` в PHPErrorCatcher. То же самое делай
со своими hash-/hex-/UUID-идентификаторами (`trace_id`, `span_id`, `session_id` - см. §5).

С этим правилом идут две молчаливые ловушки - §4.9 и §4.10.

## 3. Как выбрать правильное имя

| Что логируем | Как назвать | Почему |
|---|---|---|
| **Деньги** | `*_money`, `*_amount`, `*_price` | float. `*_sum` и `*_total` - **int**, копейки молча потеряются |
| **Счётчик** | `*_count` (или `*_cnt`) | int; `*_num`, `*_qty` - тоже int |
| **Длительность с долями** | `*_duration` | float, `1.75` останется `1.75` |
| **Длительность в целых секундах** | `*_seconds` | int |
| **Числовой идентификатор** | `*_id` (или голый `id`) | **int**: auto-increment id из MariaDB, чтобы работали `order_id > 5000` и агрегации. Не подходит для id с ведущими нулями и длиннее `PHP_INT_MAX` - см. §4.9 / §4.10 |
| **Не-числовой идентификатор** (UUID, hash, hex) | `*_id` можно, но **запиннить строкой в конфиге** (§5) | UUID не десятичный, поэтому попадает в строковый фолбэк - а тот молча станет int в день, когда кто-то передаст `"2921172"`. Пиннить, а не надеяться на фолбэк |
| **Код (не число)** | `*_code`, `*_hash`, `*_key`, `*_name`, `*_version`, `*_ip` | строка по умолчанию, правило не нужно |

**Почему не `*_ms`.** Слова `ms`, `millisecond(s)`, `sec`, `secs` намеренно **не входят** в
словарь: единица измерения в проекте одна - секунды. Ключ с `_ms` не совпадёт ни с чем и
станет строкой, а `"latency_ms": 143` рядом с `"latency_ms": "143"` - это ровно тот отказ
документа, ради которого всё написано. Пиши `*_duration` (float) или `*_seconds` (int).

**Почему не `*_time` для замеров.** `time` - это int (unix-время). Значение от
`microtime(true)` под таким именем **обрежется**: `1.75` станет `1`. Замер длительности
называется `*_duration` или `*_seconds`.

## 4. Ловушки

1. **`*_time` обрезает дроби.** `exec_time = 1.75` → `1`. Замеры - `*_duration` / `*_seconds`.
2. **`total` и `sum` - это int.** Денежное поле с таким именем теряет копейки, и никакой
   ошибки не будет. Деньги - только `money` / `amount` / `price`.
3. **camelCase не режется на сегменты.** `orderQty` - один сегмент, правило `qty` не
   сработает. Либо включи `logger.snake_case`, либо добавь запись в `exact` **строчными
   буквами**: `'exact' => ['orderqty' => 'int']`.
4. **Совпадение только по целому сегменту.** `recount`, `account`, `report`, `datetime` -
   строки. Это фича: без неё `account` стал бы числом.
5. **`_ms` / `_sec` / `_millisecond` - строки.** См. §3. Единственное исключение - голый
   ключ `millisecond`, прибитый в `exact` под один легаси-вызов
   (`tamaranga/bff/db/database.php:498`); `milliseconds` и `exec_millisecond` остаются строками.
6. **`status` - int, а `status_code` - строка.** Последний сегмент у второго - `code`, а
   `code` не слово словаря. То же у `error_code`, `response_code`. Нужен int - называй
   поле `*_status`; хочешь строку с ведущими нулями - `*_code`. Так же ведёт себя пара
   `millisecond` / `milliseconds` из п.5.
7. **Одно имя - два вида значений.** `status = 500` даст int, а `status = 'ok'` не
   приведётся и упадёт в строку - поле снова разъедется по типам. Такой ключ надо прибить
   явно: `'exact' => ['status' => 'string']`.
8. **Массивы и объекты без правила не трогаются** (иначе сломались бы запросы по вложенным
   путям), но под скалярным правилом кодируются в JSON-строку: `(int) [1,2] === 1` потерял
   бы данные молча.
9. **Id с ведущими нулями их теряет.** `order_id = '00123'` станет `123` - молча и
   необратимо. Если ключ реально носит id с нулями впереди, пиннь его строкой в конфиге (§5).
10. **Id длиннее `PHP_INT_MAX` расходится сам с собой.** `'99999999999999999999'` не
    кастуется и падает в строку, а короткое значение того же ключа остаётся int - ровно то
    смешение типов, ради которого всё это написано. Лечение то же: пин строкой в конфиге
    (§5). Обе ловушки намеренно **не** детектятся автоматически - исключения идут через
    конфиг, а не через эвристики.
11. **`word` бьёт `prefix`, поэтому `is_bot_id` - int, а не bool.** Bool-префикс срабатывает
    только если последний сегмент не дал типа. Нужен bool - назови `is_bot`.

## 5. Свои правила в проекте

Правила проекта **мержатся поверх** библиотечных, запись проекта выигрывает для того же
шаблона. Вёдра: `suffix` / `reserved` / `exact` / `word` / `prefix` (приоритет - см. §1).
Запись в `suffix` / `word` / `prefix` - это **один сегмент строчными буквами** (`rub`, не
`_rub`), `exact` - ключ целиком строчными. Неизвестное ведро или неизвестный тип молча
игнорируются: опечатка в конфиге не должна ломать логирование.

**LogSymfony** - конфигурация конструктора / DI:

```php
'contextTypeRules' => [
    'word'  => ['rub' => 'float'],          // order_rub, refund_rub → float
    'exact' => ['deliverytime' => 'int'],   // camelCase-ключ deliveryTime
],
```

**PHPErrorCatcher** - ключ `contextTypeRulesExtra` в конфиге:

```php
'contextTypeRulesExtra' => [
    'word'  => ['rub' => PhpErrorCatcher::CONTEXT_TYPE_FLOAT],
    'exact' => ['deliverytime' => PhpErrorCatcher::CONTEXT_TYPE_INT],
],
```

### Разобранный пример - пин не-числового id

`id` - это int (§2.6), но `session_id` - хеш, а `trace_id` / `span_id` - hex: значение с
буквой падает в строку, значение из одних цифр становится int. Один ключ, два json-типа,
документы молча отбрасываются. Суффикса `_string` не существует, поэтому единственное
лечение - пин через `exact`, и делать его надо в **обеих** библиотеках:

```php
// LogSymfony - конфигурация конструктора / DI
'contextTypeRules' => [
    'exact' => [
        'session_id' => 'string',   // sha256-хеш
        'trace_id'   => 'string',   // OTel hex
        'span_id'    => 'string',
        'legacy_id'  => 'string',   // id с ведущими нулями '00123'
    ],
],
```

```php
// PHPErrorCatcher - contextTypeRulesExtra
'contextTypeRulesExtra' => [
    'exact' => [
        'session_id' => PhpErrorCatcher::CONTEXT_TYPE_STRING,
        'trace_id'   => PhpErrorCatcher::CONTEXT_TYPE_STRING,
        'span_id'    => PhpErrorCatcher::CONTEXT_TYPE_STRING,
        'legacy_id'  => PhpErrorCatcher::CONTEXT_TYPE_STRING,
    ],
],
```

Один такой пин библиотека уже везёт сама - `request_id` (§2.6).

В обеих библиотеках то же самое можно сделать в рантайме:
`ContextEnricher::addContextTypeRules([...])` / `PhpErrorCatcher::addContextTypeRules([...])`.

**Слово добавляем в обе библиотеки одновременно.** Если `rub` станет float только в
LogSymfony, то `order_rub` из PHP-легаси придёт строкой - и документ отбросят.

## 6. Чего не делать

- **Не изобретай второе имя для того же самого.** `order_sum`, `order_amount` и
  `order_price` в одном проекте - это три поля вместо одного и три разных дашборда.
- **Не клади значение в message.** `"заказ 12345 на 500 руб"` не ищется и не агрегируется;
  нужно `["order_id" => 12345, "order_money" => 500]`.
- **Не называй денежное поле `sum` или `total`.** Это int - см. §4.2.
- **Не переименовывай поле, которое уже проиндексировано**, не согласовав: старые документы
  останутся со старым типом, и часть новых начнёт отбрасываться до ротации индекса.
- **Не подгоняй тип кастом на месте вызова** (`(string) $count`). Тип задаёт имя поля -
  иначе два вызывающих места разъедутся.

| Приведение | `ContextEnricher::contextTypeCorrector()` | `PhpErrorCatcher::contextTypeCorrector()` |
